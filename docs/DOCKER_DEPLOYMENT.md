# Docker Deployment Guide — Intelligent-VMS 0.1.0-rc3

Authoritative production deployment uses `compose.production.yml` managed by the PowerShell helper scripts (`scripts/setup.ps1`, `scripts/start.ps1`, `scripts/status.ps1`, `scripts/stop.ps1`).

> `docker-compose.yml` and `docker-compose.recordings.yml` are preserved strictly for legacy local development and are **not** used for production deployments.

## Core Services (`compose.production.yml`)

- **`recording-init`**: One-shot Alembic database migration runner (`alembic upgrade head`). Exits 0 before runtime services start.
- **`recording-api`**: Multi-worker FastAPI service (`VMS_API_WORKERS`, default 2) on internal `control` + `egress` networks.
- **`rtsp-recorder`**: Supervised FFmpeg stream-copy RTSP recorder (`-rtsp_flags filter_src`, `/tmp/vms-recorder.heartbeat`). Supports `single` global lease (default) or `distributed` per-camera advisory leases.
- **`storage-retention`**: Automatic scheduled recording retention worker (`RETENTION_CYCLE_SECONDS`, default 3600s) pruning only expired/low-disk **unprotected** ready recordings and writing DB audit logs.
- **`mediamtx`**: Private MediaMTX v1.21.4 media distribution (authenticated API + media reader accounts; WebRTC UDP `8189` exposed).
- **`redis`**: Session rate limiting & AI result cache (or swap to open-source BSD-3-Clause Valkey via `-Valkey` / `compose.valkey.yml`).
- **`nginx`**: TLS-terminating reverse proxy serving built frontend assets and enforcing `auth_request` on `/live/` and `/live-webrtc/`.

## Optional Overlays & Flags

| Flag / Overlay File | Purpose |
| --- | --- |
| `-BundledDb` (`compose.bundled-db.yml`) | Runs PostgreSQL 18 container (`postgres_data` volume) for single-server installs without an external DB |
| `-Ai` (`--profile ai`) | Enables CPU-based `ai-worker` (`services/ai_engine/Dockerfile`, smaller CPU PyTorch wheel) |
| `-AiGpu` (`compose.ai-gpu.yml --profile ai`) | Enables CUDA `cu128` AI worker with NVIDIA GPU reservation and `AI_GPU_MEMORY_FRACTION` |
| `-DistributedRecorders` (`compose.distributed-recorders.yml`) | Runs 2 sharded recorder workers sharing per-camera PostgreSQL advisory locks |
| `-Valkey` (`compose.valkey.yml`) | Replaces Redis 7 with BSD-3-Clause Valkey 8 (`valkey/valkey:8-alpine`) |
| `-HostMonitor` (`compose.host-monitor.yml`) | Mounts read-only host telemetry JSON generated by `scripts/host_resources.py` |

## Customer Staging / Production Deployment Commands

Provide trusted certificates `fullchain.pem` and `privkey.pem` in a private folder (e.g. `C:\VMS-Certificates`).

### Option A: Enterprise External PostgreSQL (Default)

```powershell
./scripts/setup.ps1 -TlsDirectory 'C:\VMS-Certificates'
./scripts/start.ps1 -Build -Profile small
# Or for 60+ camera production hardware:
./scripts/start.ps1 -Build -Profile enterprise -DistributedRecorders -AiGpu
./scripts/status.ps1
```

### Option B: Small Server with Bundled PostgreSQL

```powershell
./scripts/setup.ps1 -TlsDirectory 'C:\VMS-Certificates' -BundledDb
./scripts/start.ps1 -Build -BundledDb -Profile small -Valkey
./scripts/status.ps1 -BundledDb -Valkey
```

### Post-Deploy Verification

```powershell
# Verify deployed application build version
curl.exe -sk https://localhost:8443/api/version

# Verify health
curl.exe -sk https://localhost:8443/api/health
```

## Isolated Developer Validation Stack

```powershell
./scripts/start.ps1 -Validation
./scripts/status.ps1 -Validation
./scripts/stop.ps1 -Validation
```
